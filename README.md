# حفل زفاف ودّي ثلاثي الأبعاد (Next.js + Supabase Realtime)

تطبيق Next.js يُقيم حفل زفاف ودّيًا أونلاين: شخصيات ثلاثية الأبعاد بأزياء مخصّصة، وغرفة حيّة يدخلها الضيوف من هواتفهم ويظهرون كشخصيات داخل المشهد، ويصفّقون ويرسلون تهاني في نفس اللحظة.

## كيف يعمل
- **العريس** ينشئ غرفة برمز من 6 خانات، وهو من يقود الحفل ويضغط "التالي".
- **العروس** تدخل برمزها السرّي (رابط `/join?code=…` يراه العريس فقط) لتخصّص مظهرها وتقول "قبلتُ" وتوقّع من هاتفها. وإن لم تنضم، يستطيع العريس أن يملأ بياناتها وتوقيعها بنفسه.
- **الضيوف** يدخلون برابط الغرفة، يكتبون أسماءهم ويختارون مظهرهم (رجالي/نسائي، ألوان، إكسسوارات)، فتظهر شخصياتهم مصطفّة على جانبي الممشى، ويرسلون 👏 ❤️ 🎉 وتهاني نصّية.
- كل ما سبق يعمل عبر **Supabase Realtime** (Presence + Broadcast) بدون أي جدول أو قاعدة بيانات.
- حالة الحفل (المرحلة ووقت بدئها) يبثّها العريس، فمن ينضم متأخرًا يرى المشهد في مكانه الصحيح.

## التحكم
- **الحاسوب:** WASD أو الأسهم للحركة، عجلة الفأرة للتقريب، السحب لتدوير الكاميرا.
- **الجوال:** عصا الحركة أسفل اليسار، وقرص بإصبعين للتقريب.
- مواضع اللاعبين تُبثّ عبر Realtime Broadcast فقط ولا تُخزَّن في قاعدة البيانات.

## التشغيل محليًا
0. شغّل `supabase/migration.sql` في SQL Editor (ثم `002_wife_default_look.sql` إن كنت شغّلت النسخة الأولى سابقًا).
1. أنشئ مشروعًا في [Supabase](https://supabase.com) (المجاني يكفي).
2. من *Project Settings → API* انسخ **Project URL** و **anon public key**.
3. انسخ `.env.example` إلى `.env.local` وضع القيمتين فيه.
4. إن ظهر خطأ اتصال، افتح *Realtime → Settings* وفعّل **Allow public access**.
5. شغّل:
   ```bash
   npm install
   npm run dev
   ```
6. افتح `http://localhost:3000` واضغط "أنشئ غرفة الحفل". من لوحة "الحفل" انسخ رابط الضيوف ورابط العروس وأرسلهما.

## النشر على Vercel
1. ارفع المشروع إلى GitHub واستورده في Vercel.
2. أضف المتغيّرين `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY` في *Environment Variables*.
3. انشر، ثم افتح الرابط وأنشئ غرفتك.

## ملاحظات مهمة
- **المصادقة**: بريد وكلمة سر عبر Supabase Auth. الأدوار تُحدَّد في الخادم (`supabase/migration.sql`)، ورمز العروس سرّي وصالح لمرة واحدة. شارك رمز الضيوف بحرّية ورمز العروس معها وحدها.
- الغرفة تنتهي عندما يغادرها الجميع (لا يُحفظ شيء في قاعدة بيانات).
- توقيت الحفل مبني على ساعة جهاز العريس؛ إن كانت ساعة أحد الضيوف مضبوطة خطأً بفارق كبير فقد يرى المشي متقدّمًا أو متأخرًا قليلًا.
- الحفل ترفيهي، والشهادة الناتجة لا قيمة قانونية لها.

## بنية المشروع
```
app/wedding/[code]   صفحة الحفل (وأي رابط قديم /room/[code] يحوّل إليها)
app/auth, create, join   الدخول والتسجيل وإنشاء الحفل والانضمام
components/wedding/  WeddingGate (الجلسة والعضوية) · WeddingRoom · WeddingHUD · WeddingChat
                     WeddingControls · Joystick · WeddingScene (غلاف three.js) · Certificate
components/avatar/   AvatarCustomizer (تخصيص المظهر)
features/chat/       useChat: دردشة محفوظة في messages + Realtime
lib/scene.ts         مشهد three.js: الكاميرا، الحركة، التصادم، الحفل
lib/world.ts         الساحة: الكراسي، الرقص، الكعكة، الهدايا، النافورة، التصوير
lib/characters.ts    بناء الشخصيات والأزياء والإكسسوارات
lib/useRoom.ts       Supabase Realtime (Presence/Broadcast)
lib/wedding.ts       دوال الخادم: إنشاء/انضمام/حالة الحفل
supabase/            migration.sql (+ ملفات التحديث)
```

## العرض ثنائي الأبعاد (بكسل-آرت)
- `lib/scene2d.ts`: الحلقة الرئيسية (كاميرا تتبّع اللاعب، حركة، تصادم، حفل، تفاعلات).
- `lib/pixel/venue.ts`: الساحة (أرض ثابتة + مجسّمات مرتّبة بالعمق + أضواء الليل). وحدة العالم = 20 بكسل-آرت.
- `lib/pixel/avatar.ts`: شخصيات مرسومة برمجيًا من `Look` (بشرة، شعر، زي، ألوان، إكسسوارات) بأربعة اتجاهات ومشي.
- زر 🗺️ في الـHUD يعرض الخريطة كاملة. نظام LPC (`lib/lpc`, `public/game/assets`) ما زال موجودًا لكنه غير مستخدم حاليًا.

## شخصيات LPC والتخصيص
1. **الأصول المطلوبة فقط (241 ملفًا):** من جذر المشروع شغّل
   `bash tools/copy-lpc.sh /مسار/lpc-bundle/spritesheets`
   (أو `bash tools/pack-lpc.sh …` لتحصل على `lpc-needed.zip` وتفكّه داخل `public/game/assets/characters/lpc`).
2. **الكتالوج:** `lib/avatar/catalog.json` يُولَّد بـ `python3 tools/gen_lpc_catalog.py`. لإضافة صنف (تسريحة، لباس، غطاء رأس…) أضف سطرًا في قسم ITEMS داخل المولّد وأعد التشغيل ثم انسخ الأصول.
3. **قواعد الأدوار:** الأصناف الخاصة بالعروسين (`roles` في المولّد) تُفرض في الخادم: شغّل `supabase/003_avatar_items.sql` في SQL Editor.
4. **بدون أصول** يعمل المشروع بالشخصيات البكسلية المرسومة برمجيًا؛ وبمجرد توفر الأصول تظهر واجهة التخصيص الكاملة تلقائيًا.
